Trace Unit
==========

Overview
--------

The Trace Unit is a hardware module for real-time debugging and profiling of the RISC-V processor core. It monitors core execution by capturing events (exceptions, system calls, memory operations) and branch divergence (jumps, branches, calls), generating trace packets transmitted via UART for offline analysis.

The module operates non-intrusively with minimal overhead on core execution, supporting 24-bit timestamps, PC-based triggers, and configurable buffering to handle event bursts.

Features
~~~~~~~~

* CPU event tracing (exceptions, interrupts, system calls, memory operations)
* Branch divergence tracing (non-sequential control flow)
* 24-bit timestamp for temporal correlation
* Program Counter trigger for selective tracing start
* Configurable packet FIFO (32 entries in the current SoC integration)
* Automatic serialization to UART
* Core halting on buffer full to prevent data loss
* Interrupt on buffer full/empty

Architecture
------------

The Trace Unit consists of three main modules:

* **Registers**: Manages configuration, control and status registers
* **Packetizer**: Generates trace packets from CPU events and divergence detection
* **Serializer**: Serializes packets into byte stream to UART

Signal interface
~~~~~~~~~~~~~~~~

Port directions are relative to the ``trace_unit`` module. The register
signals are the local SoC memory-mapped interface, while the CPU and UART
signals are sideband interfaces. Addresses are 2-bit word indices and
``write_strobe_i`` enables individual bytes of ``write_data_i``.

Operation
---------

Packet Types
~~~~~~~~~~~~

The packetizer stores a fixed 64-bit packet internally. The serializer sends
the most-significant byte first (``raw[7]`` through ``raw[0]``), and emits only
the bytes required by the packet type. There is no additional ``0xAA`` sync
byte in the current RTL. The two most-significant bits of byte 0 identify the
packet type:

.. list-table:: Packet type codes
   :header-rows: 1
   :widths: 20 18 62

   * - Code
     - Name
     - Meaning
   * - ``2'b00``
     - ``EVENT_PACKET``
     - A selected CPU event identified by the six-bit event number.
   * - ``2'b01``
     - ``DIVERGENCE_PACKET``
     - A non-sequential PC transition.
   * - ``2'b10``
     - ``OVERFLOW_PACKET``
     - The 24-bit timestamp counter wrapped.
   * - ``2'b11``
     - Reserved
     - Not generated by the packetizer.

Event packet
^^^^^^^^^^^^

The event number is copied from ``trace_interface_i.info``. The timestamp is
the 24-bit packetizer counter at packet creation time. The byte layout on the
UART stream is:

.. code-block:: text

   Without timestamp (1 byte):
   byte 0: [7:6] packet type = 00 | [5:0] event number

   With timestamp (4 bytes):
   byte 0: [7:6] packet type = 00 | [5:0] event number
   byte 1: timestamp[23:16]
   byte 2: timestamp[15:8]
   byte 3: timestamp[7:0]

Divergence packet
^^^^^^^^^^^^^^^^^

The packetizer compares the current valid PC with the previous valid PC. The
``delta_pc`` field is the signed 32-bit two's-complement value
``current_pc - previous_pc``. The byte layout is:

.. code-block:: text

   Without timestamp (5 bytes):
   byte 0: [7:6] packet type = 01 | [5:0] reserved = 0
   byte 1: delta_pc[31:24]
   byte 2: delta_pc[23:16]
   byte 3: delta_pc[15:8]
   byte 4: delta_pc[7:0]

   With timestamp (8 bytes):
   byte 0: [7:6] packet type = 01 | [5:0] reserved = 0
   byte 1..4: delta_pc[31:0], most-significant byte first
   byte 5: timestamp[23:16]
   byte 6: timestamp[15:8]
   byte 7: timestamp[7:0]

Overflow packet
^^^^^^^^^^^^^^^

The overflow packet is one byte:

.. code-block:: text

   byte 0: [7:6] packet type = 10 | [5:0] reserved = 0

It is queued when the timestamp reaches ``24'hFFFFFF``. If an event or
divergence packet is created in the same cycle, that packet has priority and
the overflow notification is held pending for a later cycle.

Timestamp framing
^^^^^^^^^^^^^^^^^

The serializer's ``enable_timestamp_i`` input is the OR of the event and
branch timestamp controls. Therefore, when either timestamp control is set,
both event and divergence packets are serialized with their three-byte
timestamp field. The timestamp is still present in the internal packet when
timestamping is disabled; it is simply omitted from the UART stream.

Event Tracing
~~~~~~~~~~~~~

When enabled, the Trace Unit captures configurable events from the core:

* **Instruction faults**: Misaligned, access fault, illegal instruction
* **Breakpoint**: Debug breakpoint
* **Load/Store operations**: Memory operations and related faults
* **System calls**: User-mode and machine-mode ecall
* **Handler return**: MRET instruction
* **Sleep**: WFI instruction
* **Branch/Jump**: Control flow operations
* **CSR operations**: Control Status Register accesses

Branch Tracing
~~~~~~~~~~~~~~

The module compares the current PC with the previous one. If it is not
``previous_pc + 4``, ``previous_pc + 2`` for a compressed instruction, or the
same PC, it generates a divergence packet containing the PC delta.

Divergence detection activates after the first valid PC (or after trigger PC if enabled) to avoid initial false positives.

Timestamp
~~~~~~~~~

The 24-bit counter increments every cycle when timestamping is enabled. Upon reaching 0xFFFFFF, it generates an Overflow Packet and continues from 0.

Trigger PC
~~~~~~~~~~

When enabled, branch tracing starts only when the core reaches the specified PC. Useful for tracing specific code sections.

Core Halting
~~~~~~~~~~~~

When the buffer is full, the ``halt_core_o`` signal is asserted to stop the core and prevent packet loss. The core resumes when buffer space becomes available.

Serializer FSM
--------------

The serializer manages packet transmission to UART through a 3-state FSM:

**IDLE**

* Waits for packets in buffer and UART not full
* Reads packet from buffer
* Transition to LATCH

**LATCH**

* Latches the packet and extracts its type from the first serialized byte
* Transition to DATA

**DATA**

* Transmits payload bytes sequentially
* Byte count depends on packet type and timestamp enable:

  * OVERFLOW: 1 byte
  * EVENT: 1 byte (no timestamp) or 4 bytes (with timestamp)
  * DIVERGENCE: 5 bytes (no timestamp) or 8 bytes (with timestamp)

* Returns to IDLE after last byte

Timing Characteristics
----------------------

* **Timestamp resolution**: 1 clock cycle
* **Timestamp range**: 0 to 16,777,215 cycles (24-bit)
* **Packet generation latency**: 1 clock cycle
* **Serialization rate**: Limited by UART TX speed
* **Buffer depth**: Configurable (32 packets in the current SoC integration)

For a 50 MHz clock:

* **Timestamp resolution**: 20 ns
* **Timestamp overflow**: ~335 ms
* **Max sustained event rate**: Depends on UART baud rate

Integration Guidelines
----------------------

UART Connection
~~~~~~~~~~~~~~~

The Trace Unit connects directly to the UART TX buffer. The ``uart_tx_full_i`` signal handles backpressure when UART cannot accept data.

Core Halting
~~~~~~~~~~~~

When the buffer is full, ``halt_core_o`` stops the core to prevent packet loss. Ensure the core supports halting via this signal.

Buffer Sizing
~~~~~~~~~~~~~

Buffer size must be chosen based on:

* Expected event rate
* UART baud rate
* Core halting tolerance

A larger buffer reduces core halt probability but increases latency and area.

Packet Parsing
~~~~~~~~~~~~~~

Packets transmitted via UART must be parsed offline:

1. Read byte 0 and extract the packet type from its two MSB bits
2. Select the packet length from the type and timestamp configuration
3. Decode the event number or big-endian PC delta from the remaining payload
4. Read the optional three-byte big-endian timestamp when enabled
5. Reconstruct control flow from divergence deltas
6. Correlate events via timestamp

Limitations
-----------

* 24-bit timestamp (overflow after ~335 ms at 50 MHz)
* Fixed buffer size at synthesis time
* No packet compression
* Single trace interface (only one core supported)
* Requires dedicated UART for trace output
* Core halting on buffer full may impact real-time timing
